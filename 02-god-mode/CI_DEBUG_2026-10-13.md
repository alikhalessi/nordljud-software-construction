# CI defect log: distinct lemma count vs learning records

**Date:** 13 October 2026. **Method:** Condition B — God Mode.
**Initial CI:** GitHub Actions `38317088266`, outcome **FAIL** (2 of 3 tests passed). `npm test` halted the workflow; `tsc` and `next build` CI steps were skipped.

## Observed failure

`test/learning-data.test.mjs:17` asserted that the 456 entries in the common A2 dataset had 456 distinct values of `v`. The log showed `455 !== 456`. The original source has **456 sense records and 455 unique written lemmas** because `sticka` appears twice with different senses, both on page 37: `knit` (present `stickar`) and `sting, prick; to leave (colloquial)` (present `sticker`). All four CEFR levels contain these two records in the same positions with the same meanings but different example sentences.

## Resolution

1. Preserve all four frozen common datasets unchanged; do not delete a sense to make the test pass.
2. Update the assertion to expect **456 records / 455 unique spelled lemmas** and explicitly verify the two `sticka` meanings.
3. Repair a related UI bug: the original God Mode dictionary keyed React rows and selection by `item.v`; duplicate `sticka` values made distinct senses ambiguous. New sense identity is `v + "::" + meaning`; selected sense and Favorites now preserve both meanings independently across A2/B1/B2/C1.
4. The code still describes the verb collection as 456 in some UI copy; interpret it as 456 **entries**, not 456 unique spellings. Update this copy in a later measured correction if appropriate.
